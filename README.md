# 精算アプリ

友達と割り勘を管理するモバイル向け Web アプリ。アカウント登録なしで使えて、
グループは招待リンクを受け取った人だけがアクセスできます。

## 機能

- グループ作成・名前変更・削除（作成者のみ）
- **招待リンクによる参加** — リンクを持たない人にはグループの中身が一切見えない
- **招待リンクの再発行と参加者の追放** — 流出したリンクを無効化できる
- CSV エクスポート（旅行後に記録を手元に残せる）
- ホーム画面に追加できる（PWA マニフェスト同梱）
- メンバーの追加・削除（削除時は消えるデータの内訳を警告）
- 支払いの記録・編集・削除（均等割り / 個別金額指定）
- メンバーごとの精算済み / 未精算ステータス切り替え
- 最小回数の送金で済む精算方法を自動計算
- 3 秒間隔のポーリングで他の人の更新を自動反映
- 管理者モード（全グループの閲覧・管理）

## アクセス制御の仕組み

ログインもパスワードもありません。代わりに、初回アクセス時にサーバーが
ランダムな値を **httpOnly Cookie** として発行し、それが端末の身元になります。

| 役割 | 権限 |
|---|---|
| 管理者 | すべてのグループを閲覧・編集・削除 |
| 作成者 (owner) | そのグループの削除・名前変更・**招待リンクの発行と再発行**・参加者の追放 |
| 参加者 (member) | そのグループの支払い追加・編集・精算チェック・自主退出 |
| それ以外 | 403。存在の有無すら分からない |

判定は**すべてサーバー側**（`lib/session.ts` の `authorizeGroup`）で行い、
全 API ルートの先頭で呼び出しています。

Cookie に入る値そのものは保存せず、SHA-256 ハッシュだけを `app_users` に置くため、
データベースが漏れてもセッションの偽装はできません。

**招待リンクは作成者にしか渡りません。** 参加者が API を叩いてもトークンは含まれず、
画面上も「参加者一覧」しか出ません。誰がグループに入ってくるかを作成者が完全に把握できます。

管理キーの誤入力にはレート制限（10 分あたり 5 回）がかかりますが、**正しいキーは制限の
対象外**です。共有ネットワーク上の他人の誤入力で、本人が自分の管理画面から締め出される
のを避けるためで、総当たり側は定義上いつも失敗するので効果は変わりません。

### アクセスの取り消し

作成者は共有シートから招待リンクを作り直せます。以前のリンクはその場で無効になり、
すでに参加している人はそのまま残ります。個別の端末のアクセス解除も同じ画面から行えます。

**追放だけでは不十分な場合があります。** 相手が古いリンクを持っていれば入り直せるため、
完全に締め出すには「解除」と「リンクの作り直し」の両方が必要です。この挙動は
`tests/api/access.test.ts` でテストとして固定しています。

### 制約

- Cookie を消す / 端末を変えるとアクセス権を失います。招待リンクを開き直せば復帰できます。
- 招待リンクを転送された人も参加できます。ログインなしの構成では原理的に防げません。
- 参加者は「人」ではなく「端末」単位です。同じ人が複数の端末から入ると別々に並びます。

### 匿名 ID の行が作られるタイミング

`app_users` の行は、**グループを作る / 招待リンクで参加する / 管理者になる**ときにだけ
作られます。閲覧しただけでは作られません。アクセスのたびに作っていると、Cookie を
保持しないクローラーが 1 リクエストごとに 1 行増やしてしまうためです。

孤児行の掃除と管理者権限の失効には `scripts/db-maintenance.mjs` を使います
（既定はドライラン、`--yes` で実行）。

```bash
node scripts/db-maintenance.mjs                              # 現状の確認のみ
node scripts/db-maintenance.mjs --prune-orphans --yes        # 24時間以上前の孤児を削除
node scripts/db-maintenance.mjs --revoke-admins --yes        # 全端末の管理者権限を失効
```

### 同時編集

支払いには `revision` があり、編集画面を開いた時点の値を保存時に送ります。
その間に他の人が同じ支払いを保存していると **409 を返して上書きを拒否**します。

グループ全体の `revision` ではなく**支払いごと**に持たせています。グループ単位だと
誰かがメンバーを増やしただけで無関係な編集まで弾かれてしまうためです。精算済みの
チェックは支払いの編集ではないので、リビジョンを動かしません。

### 支払いを編集したときの精算済みの扱い

編集は splits を作り直しますが、**対象に残っていて負担額も変わっていない人の
「精算済み」は引き継がれます。** 負担額が変わった人だけ未精算に戻ります
（settled した金額と請求額が食い違うため）。

## 技術構成

- Next.js 16（App Router） / TypeScript
- Tailwind CSS
- Neon Postgres（`@neondatabase/serverless`）
- SWR（ポーリングによる自動更新）

## セットアップ

```bash
npm install
cp .env.local.example .env.local   # DATABASE_URL と ADMIN_KEY を設定
npm run dev
```

テーブルは初回アクセス時に自動作成されます（`lib/db.ts` の `ensureSchema`）。

## テスト

```bash
npm run test:unit    # 精算計算と端数処理（DB 不要・1秒未満）
npm run test:api     # 権限・CRUD・カスケード削除
npm run test:e2e     # ブラウザ操作（Playwright / WebKit）
npm test             # 上記すべて
npm run test:health  # 本番への読み取り専用の死活監視
```

| 層 | 守る対象 | 実行時間 |
|---|---|---|
| 単体 | `computeBalances` / `splitEqually` | 1 秒未満 |
| API 統合 | 権限境界、精算、カスケード削除、CSV | 約 2 分 |
| E2E | 画面が実際に動くか（モバイル Safari + デスクトップ Chrome） | 約 2 分 |

**API と E2E は本番とは別の Neon プロジェクト**（`TEST_DATABASE_URL`）を使います。
`scripts/with-server.mjs` がこれを `DATABASE_URL` に差し替えてサーバーを起動するため、
テストが本番データに触れることはありません。

接続文字列は `.env.local` ではなく **`.env.test.local`** に置きます。
`vercel env pull` は `.env.local` を丸ごと書き換えるため、同じファイルに入れておくと
env を引き直すたびに消えてしまうからです。

E2E 層は他の層では見つけられない不具合を担当します。削除ボタンはかつて
`window.confirm()` に依存しており、アプリ内ブラウザがダイアログを抑制すると
無反応になっていました。API テストでは検出できません。

### 自動実行

- **`.github/workflows/ci.yml`** — push / PR のたびに全テスト
- **`.github/workflows/health.yml`** — 毎週月曜 9:00 JST に本番の死活監視

CI には GitHub のシークレットとして `TEST_DATABASE_URL` と `ADMIN_KEY` が必要です。

## デプロイ

Vercel にデプロイし、Marketplace から Neon を追加すると `DATABASE_URL` が自動で設定されます。
`ADMIN_KEY` は Vercel の環境変数に手動で追加してください。
